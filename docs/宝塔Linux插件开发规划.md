# 网站监控报表：宝塔 Linux 面板插件开发规划

## 1. 项目目标

开发一款可安装到宝塔 Linux 面板的第三方插件，在面板内完成网站访问日志采集、聚合、查询和可视化展示。

最终交付物不是独立网页，而是一个符合宝塔插件目录规范、可以安装/升级/卸载的离线插件包。

插件显示名称：`网站访问分析`  
插件内部标识：`WebAnalytics`  
插件目录：`/www/server/panel/plugin/WebAnalytics/`  
开发者标记：`Meiam`

命名说明：`WebAnalytics` 直接表达网站访问与流量分析用途；安装目录、`info.json` 中的 `name`、后端文件名和后端类名必须保持一致。`Meiam` 仅写入 `info.json` 的 `author` 等开发者信息，不进入插件名称、目录名或程序入口名。

### 目标功能

- 概览：PV、UV、独立 IP、流量、请求数、实时流量、每秒请求及趋势对比。
- 网站列表：服务器全部站点的核心指标和状态对比。
- 蜘蛛统计：主流搜索引擎蜘蛛占比、趋势和明细。
- 客户端统计：浏览器、操作系统、设备类型及 PC/移动端占比。
- IP 统计：访问次数、流量、状态码和最后访问时间排行。
- URI 统计：页面/接口访问排行、流量和错误率。
- 错误日志：40x、50x 日志筛选、详情和 CSV 导出。
- 网站日志：组合条件查询、详情和 CSV 导出。
- 统计报告：周报、月报生成；PDF 和邮件推送列为第二阶段。
- 全局设置：采集开关、保留周期、排除规则、统计口径和资源限制。

### 非目标

- 不复制宝塔官方插件的源码、商标、图标或专有素材。
- 首版不建设跨服务器集中日志平台。
- 首版不依赖外部 SaaS、远程数据库或公网服务。
- 首版不修改业务网站代码，不通过插入前端脚本追踪用户。

## 2. 兼容范围

### 首要验收环境

- 宝塔 Linux 面板 v11.x 正式版。
- Nginx 作为首要 Web 服务环境。
- Ubuntu 22.04/24.04、Debian 12、Rocky Linux 9。
- Python 使用宝塔面板自带运行环境，业务代码保持 Python 3 兼容。

### 兼容性扩展

- 宝塔 v10.x：仅作为后续兼容性扩展，单独回归后再决定是否列为正式支持。
- 宝塔 v9.x 及更早版本：不属于首版支持范围。
- Apache：作为第二个 Web 服务适配器，在 Nginx 版本稳定后验收。
- OpenLiteSpeed、Docker 内部日志、远程日志：不属于首版正式支持范围。

> 宝塔公开插件开发文档的基础格式较早，不能仅凭文档宣称兼容。每个正式支持版本都必须在真实面板中完成安装、接口和卸载测试。

## 4. 系统架构

```text
Nginx access_log syslog
        │
        ▼
/tmp/webanalytics.sock（Unix Datagram）
        │
        ▼
systemd 实时采集服务
        │
        ├── JSON 解析、排除规则、蜘蛛/客户端识别
        ├── /www/wwwlogs 增量读取（历史回溯/故障恢复）
        ▼
SQLite（WAL + 批量事务）
        │
        ├── 分钟/小时/天聚合
        ├── IP、URI、客户端、蜘蛛维度
        └── 可配置的近期原始记录
        ▼
WebAnalytics_main.py（宝塔面板内 POST API）
        │
        ▼
index.html + static（报表界面）
```

### 采集策略

1. 从宝塔站点数据库发现站点，不接受前端传入任意配置或日志文件路径。
2. 为站点配置追加带唯一标记的 Nginx syslog 转发指令，实时发送到插件独立的 `/tmp/webanalytics.sock`。
3. 配置修改前逐站备份；修改后必须执行 `nginx -t`，成功才重载，失败立即回滚。
4. systemd 采集服务批量解析 socket 数据并按秒级批次写入 SQLite，不开放 TCP/UDP 公网端口。
5. `/www/wwwlogs` 增量解析保留为历史回溯和故障恢复能力，记录设备号、inode、offset、大小和修改时间。
6. 历史回溯识别日志轮转、重命名和截断，并设定时间/行数预算。
7. 插件使用自己的 socket 名称，不连接、复用或修改宝塔官方 `/tmp/bt-monitor.sock`。

### 实时服务方案

- 安装独立的 `webanalytics.service` systemd 单元，由系统负责开机启动和异常重启。
- 使用 Unix Datagram Socket 接收 Nginx syslog，正常数据延迟目标小于 3 秒。
- 不创建宝塔计划任务或 `/etc/cron.d` 条目。
- 周报、月报、数据保留清理等低频维护任务在阶段 C 另行设计，不与实时采集耦合。
- 卸载前先移除站点转发配置并通过 `nginx -t`，再停止服务和删除 socket，避免 Nginx 持续发送到失效路径。

## 5. 统计口径

所有指标必须在界面提示中写清口径：

- 请求：被纳入统计的每一条访问日志。
- PV：排除静态资源后的页面或接口请求；排除扩展名列表可配置。
- 独立 IP：选定时间范围内去重后的客户端 IP。
- UV：同一天内 `IP + User-Agent` 的不可逆哈希去重，是服务端日志估算值，不等同于浏览器 Cookie 用户。
- 流量：日志中的响应字节数之和，不包含 TLS、请求体及网络层开销。
- 实时流量：最近一个完整分钟的响应字节数。
- 每秒请求：最近一个完整分钟的请求数除以 60。
- 蜘蛛：按 User-Agent 规则识别，并区分百度、Google、Bing、搜狗、360、神马等。
- 错误：HTTP 状态码 400–599；40x 与 50x 可分别筛选。
- 时间：数据库统一存 Unix 时间戳，展示和报告按面板/系统时区转换。

## 6. 数据模型

### 核心表

- `schema_version`：数据库迁移版本。
- `sites`：站点标识、域名、日志路径、启用状态、Web 服务类型。
- `file_cursors`：日志文件 inode、offset、文件大小、更新时间。
- `metric_minute`：站点每分钟 PV、请求、流量、错误、UV 基数。
- `metric_hour`：小时聚合，用于 7 天和 30 天趋势。
- `metric_day`：天聚合，用于长期报告。
- `dimension_day`：IP、URI、蜘蛛、浏览器、系统、设备等维度日统计。
- `recent_requests`：可选的近期访问记录，默认保留 7 天并设置容量上限。
- `error_requests`：错误请求明细，默认保留 30 天并设置容量上限。
- `report_snapshots`：已生成周报/月报的数据快照。

### 数据库策略

- 使用 Python 标准库 `sqlite3`，开启 WAL。
- 聚合表使用联合唯一键和 UPSERT。
- 原始日志表按时间、站点、状态码、IP、URI 建立必要索引，避免过度索引。
- IP 只在用户选择保留明细时存储；支持哈希化 IP 的隐私模式。
- 每日执行保留期清理和 `ANALYZE`；`VACUUM` 仅手动或达到阈值时执行。
- 设置数据库体积软上限，超限时先停止原始明细写入，聚合统计继续工作，并在界面告警。

## 7. 后端 API 规划

前端统一使用 POST，避免使用宝塔文档提示的保留参数名 `action`、`s`、`name`、`a`。

### 查询接口

- `get_overview(args)`：核心指标和同比/环比。
- `get_trend(args)`：分钟、小时、天趋势。
- `get_sites(args)`：站点列表与监控状态。
- `get_spiders(args)`：蜘蛛占比、排行和趋势。
- `get_clients(args)`：设备、浏览器和系统统计。
- `get_ip_rank(args)`：IP 排行与分页。
- `get_uri_rank(args)`：URI 排行与分页。
- `get_errors(args)`：错误日志组合筛选。
- `get_requests(args)`：网站日志组合筛选。
- `get_reports(args)`：周报、月报列表与数据。
- `get_settings(args)`：全局和站点配置。
- `get_health(args)`：采集延迟、数据库大小、最后错误。

### 写操作接口

- `save_settings(args)`：保存全局或站点配置。
- `set_site_enabled(args)`：启停单站采集。
- `run_backfill(args)`：按确认范围回溯历史日志。
- `rebuild_period(args)`：重建指定站点和日期的聚合。
- `clear_data(args)`：按站点和日期清理插件数据，必须二次确认。
- `export_csv(args)`：生成受控临时文件并提供面板内下载。

所有接口返回统一结构：`success`、`message`、`data`、`request_id`。

## 8. 前端规划

界面参考用户提供的截图，采用宝塔面板兼容的高密度管理后台风格：

- 左侧为插件内部模块导航。
- 顶部提供站点、时间范围、统计粒度和刷新控制。
- 首屏展示 7 个核心指标及趋势图。
- 表格页面支持分页、排序、搜索和 CSV 导出。
- 大查询展示加载状态，可取消或缩小范围。
- 数据为空时明确区分“暂无访问”“日志未开启”“采集异常”。
- 所有可能影响站点配置、清空数据、执行历史回溯的操作都需要确认。
- 不加载外部 JS/CSS/CDN；静态资源全部随插件包交付。
- 前端不依赖当前工作区的独立 Sites/Next.js 运行时，最终产物编译为宝塔插件可直接加载的静态资源。

## 9. 安全与隐私

- 仅通过宝塔面板登录会话访问插件接口，不开放匿名公网 API。
- 不使用不继承面板会话的动态公共路由；若未来必须使用，需单独实现严格 `_check` 鉴权。
- 所有站点 ID、时间范围、排序字段、分页大小均使用白名单校验。
- 日志路径必须解析并确认位于允许的日志目录内，禁止目录穿越和任意文件读取。
- SQL 全部使用参数绑定，排序字段不得直接拼接用户输入。
- URI、Referer、User-Agent 等不可信日志字段在前端统一转义，防止存储型 XSS。
- CSV 处理公式注入，对以 `= + - @` 开头的字段进行安全转义。
- 导出文件使用随机名和短期失效机制，完成后自动清理。
- 配置修改采用临时文件、校验、原子替换；涉及 Web 服务配置时先备份并运行语法检查。
- 安装包不下载外部代码，不加密源码，不向第三方发送日志、IP 或服务器信息。
- 卸载默认保留数据备份；彻底删除数据必须由用户显式选择。

## 10. 安装、升级与卸载

### 安装

- 校验宝塔面板、Python、磁盘空间和日志目录。
- 创建插件数据目录和最小权限文件。
- 初始化 SQLite 与配置。
- 安装并启动 `webanalytics.service`，创建独立 Unix Socket。
- 备份并写入 Nginx syslog 转发配置，通过语法检查后重载。
- 全新安装先初始化空库，systemd 服务随后在后台完整导入当前及轮转访问日志；导入状态与游标持久化，服务重启可续跑；卸载时删除统计库。

### 升级

- 安装脚本识别 `update` 参数。
- 升级前备份配置和数据库。
- 使用带版本号的数据库迁移，迁移失败自动回滚。
- 保留采集游标，避免升级后重复计数。

### 卸载

- 移除带标记的 Nginx 转发配置，语法检查成功后重载。
- 停止并删除本插件 systemd 服务和 Unix Socket。
- 默认把数据库和配置移动到带时间戳的备份目录。
- 不删除原始网站日志，不修改其他计划任务或官方监控 socket。

## 11. 性能预算与保护

首版目标以“不给业务网站增加明显负担”为优先：

- 空闲采集任务内存目标低于 80 MB。
- 单批数据库事务默认不超过 5,000 行。
- 单次采集默认运行不超过 45 秒，剩余数据延后处理。
- 查询接口默认时间跨度 7 天，最大跨度受接口和粒度限制。
- 明细接口强制分页，单页不超过 200 条。
- 历史回溯必须显示预计范围并由用户主动启动。
- 检测磁盘不足、数据库锁、日志不可读和采集积压，向 UI 返回健康告警，而不是无限重试。

### 完成定义

- 核心指标与测试日志核对误差符合已声明口径。
- 连续运行 24 小时无重复计数、采集卡死或明显资源异常。
- 不开放额外公网端口，不请求外部服务。
- 文档包含安装方式、统计口径、资源影响、备份恢复和故障排查。

## 13. 分阶段实施

### 阶段 A：插件骨架与最小闭环

- 清理独立网站原型的运行时依赖，保留可复用的视觉设计。
- 建立宝塔插件标准目录、`info.json`、安装脚本和后端入口。
- 完成站点发现、Nginx syslog 配置、Unix Socket 服务、SQLite 和实时写入。
- 完成概览页、站点选择、今日趋势和采集健康状态。
- 产出第一个可安装测试包。

### 阶段 B：完整统计模块

- 网站列表、蜘蛛、客户端、IP、URI 统计。
- 错误日志与网站日志的分页、筛选、详情和 CSV 导出。
- 全局与单站配置、排除规则、历史回溯、数据清理。
- Apache 适配。

### 阶段 C：报告与发布质量

- 周报、月报快照。
- PDF 与邮件推送在依赖、安全和资源影响评审通过后加入。
- 多发行版、宝塔 v11.x 不同正式版本兼容回归；v10.x 另行评估。
- 安装包、用户手册、变更记录和发布检查清单。

## 14. 开发前需要确认的产品决策

建议使用以下默认值开始实现；如无异议，阶段 A 按此执行：

1. 首要环境：宝塔 v11.x 正式版 + Nginx，Apache 在阶段 B 加入。
2. 实时延迟：目标小于 3 秒，使用 systemd 管理的 Unix Socket 常驻采集进程。
3. 首次安装：初始化空库并完整导入现存日志，完成后持续实时统计新请求；重装同样从日志重新生成。
4. UV：按日 `IP + User-Agent` 哈希估算，并在 UI 明示。
5. 原始访问明细：默认保留 7 天；错误明细保留 30 天。
6. 数据位置：插件目录内 SQLite；卸载默认备份数据。
7. 外部连接：默认完全离线，不发送遥测。

## 15. 主要风险

- 宝塔公开插件文档版本较早：通过真实 v11.x 正式版面板测试和参考当前插件行为降低风险。
- 不同站点日志格式不一致：格式探测、解析适配器和“不支持格式”告警，不静默误算。
- 大流量站点日志量巨大：增量游标、批量事务、运行预算、聚合优先和数据容量上限。
- UV 无 Cookie 无法精确：明确标注估算口径，不宣称精确用户数。
- CDN 后真实 IP 缺失：默认统计日志中的客户端地址；增强日志格式必须由用户主动开启。
- 日志中包含恶意内容：从采集、存储、展示到导出全链路按不可信输入处理。
